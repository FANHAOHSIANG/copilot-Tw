# Copilot tw wide.41：測速提醒恢復與高德輸入診斷

版本 `9.3.1-wide.41-alert-recovery`／`26110753`，沿用既有簽章，可覆蓋 wide.40。

## 測速顯示修正

- 提醒結果不再要求與最新 GPS 完全同一時間；最多接受 3 秒內的計算結果，且檢查位置差、方向轉變、停車與定位有效性，扣除已行進距離。已接近／通過的點不沿用。
- 道路候選超過 12 條時保留成本較低的 12 條，不再將全部歷史重置。
- 測速點位於後方，或目前方向與相機道路執法方向相反時不採用該軌跡提醒；彎折道路可能較晚才符合前方條件。
- 空的軌跡結果不覆蓋原本已確認的測速點；保留原道路速限。
- 道路配對找不到點時，另用完整固定點清單做同向、前方走廊與持續接近判斷。至少兩筆、間隔 1 秒、距離減少超過定位門檻才顯示；不恢復停車時的周圍無差別播報。
- 這條備援顯示「同向候選／道路未確認／直線距離」，不宣稱已完成道路配對。執法方向不明的點不經此路徑播報。彎道、方向原始資料不準、平行道路仍可能漏報或誤報，不能宣稱全台每點都能用。
- 已知道路層級沿用平面／高架文字及語音；備援無法確認層級時標示未標明，使用原本聲音 A「前方測速照相」。1 公里內啟用播報，500 公尺內螢幕周圍紅光警示。
- 上述均為畫面／語音，不將放寬的候選資料注入 C4 控制。

## 高德一般版 → C4

檢查發現：接收器有監聽共用高德 action，但來源閘門在發送套件不明時，手機版僅接受兩種 `com.autonavi.minimap.*` action。這可能是一般版沒有資料的原因之一，但沒有取得使用者實機廣播，不能據此斷言已找到全部原因。

本版加入輸入診斷，保留來源隔離及原解析規則；不把來源不明的共用廣播一律認作一般版，也不把通知文字轉為 C4 控制資料。**尚未證實一般版已能餵給使用者的 C4。**

切換到高德一般版並開始一條導航路線後，在投屏／導航狀態的「Carrot 導航資料」查看：
- 接收／允許／過濾次數及最近時間。
- 選擇的地圖、系統提供的發送套件、廣播 action。
- 解析入口 KEY_TYPE 是否存在。
- 通過來源過濾的 stream 與時間（只是手機端階段，不代表網路送達或 C4 接收）。

切換地圖會清零診斷，不記錄地址、座標或完整廣播內容。若仍無資料，這一區的截圖可區分沒廣播、來源遭擋、缺少協議欄位，與後續傳輸問題。

## 驗證與重建

48 項 Java 離線檢查涵蓋原方向／語音測試及新增背景時差、21 條候選、空結果覆蓋、道路速限保留、同向接近備援、停車／反向／過期拒絕與高德診斷。完整道路合成回放結果另列 verification。這些不等於 Android 實機、音訊或 C4 接收測試。

`src/` 是新增提醒及診斷 helper；`smali/` 是實際 APK 修改的類別。基底為 wide.40，重建方法沿用 wide.40 的環境變數與 `python3 rebuild.py`；原私人簽署金鑰需自行提供，未提交。Java helper 可用 Java 8 語法編譯 src/*.java 與 tests/*.java，再執行 AlertChecks、RecoveryChecks。

全量對照：539 組合成道路案例，兩版各 522 組形成提醒、17 組未形成；各有 9 組反向回放異常待查，沒有新增異常組。詳見 [驗證紀錄](verification/README.md)。
